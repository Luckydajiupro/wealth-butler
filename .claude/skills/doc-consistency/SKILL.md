# 跨文档一致性检查

本项目有 14+ 份文档，历史上多次出现"改了一处口径、其他文档没跟上"的跨文档矛盾（需求文档/架构文档/业务流程文档反复做过口径审计）。**改代码时，如果涉及字段、接口、规则、权限、事件格式，必须连带检查受影响文档是否要同步改。**

## 1. 各文档管什么（权威源在哪）

| 内容 | 权威文档 |
|---|---|
| 功能清单、RBAC 矩阵、事件消息格式、验收标准 | 《智能财富管家系统-项目需求文档.md》（最高权威） |
| 表结构、字段定义 | 《表设计文档.md》 |
| 接口契约、权限字符串 | 《API接口设计文档.md》 |
| System Prompt、意图分类、工具 schema | 《Agent设计文档.md》 |
| 架构图、ADR、部署视图 | 《架构设计文档.md》 |
| 流程图、时序图 | 《业务流程说明.md》 |
| 功能清单与需求分析 | 《项目功能清单与需求分析.md》 |
| 规则明细 | 《研判规则提取与落地方案.md》、根目录《用户研判规则》 |

**冲突原则**：文档之间出现口径不一致时，以《需求文档》为准，并反向修正其他文档。

## 2. 典型联动场景（改一处必查这些）

- **改表字段** → 《表设计文档.md》+《需求文档》对应章节 +（若字段被 API 暴露）《API接口设计文档.md》+（若被 SQL/Cypher 用）《Agent设计文档.md》
- **改接口路径/权限** → 《API接口设计文档.md》+《需求文档》§7.1 +《Agent设计文档.md》§5.1（意图分类的权限）
- **改规则阈值/规则编号** → 《研判规则提取与落地方案.md》+《Agent设计文档.md》§6+《需求文档》§5.2 +《业务流程说明.md》
- **改事件消息格式** → 《需求文档》§2.4 +《架构设计文档.md》§4 时序图 +《业务流程说明.md》§4
- **改技术栈/部署** → 《需求文档》§2.5 +《架构设计文档.md》§3 +《项目功能清单与需求分析.md》技术栈表

## 3. 触发时机

- 编码时改了上述任一内容 → 同步检查文档并更新（配合 doc-versioning 更新版本号）。
- 文档本身改动 → 检查是否牵涉其他文档口径。
- code-review 时 → 把跨文档一致性作为 review 项之一（对应 code-review 的 §4 交叉一致性核对）。

## 4. 检查方法

- 改动后，用关键词在 `docs/` 下全量搜索（如改了 `fin_transaction` 的字段，搜所有文档里出现的 `fin_transaction`），逐个确认新旧口径一致。
- 检查对象包括 mermaid 图（架构文档/业务流程说明里的图最容易漏改，图内文字与正文文字都要查）。
- 不确定某文档是否受影响时，宁可多查一遍，不要留"应该没影响"的假设。

## 5. 交付前自检

- 本次改动涉及的类型（字段/接口/规则/权限/事件/技术栈）有没有对应到 §2 的联动场景，逐一检查过受影响文档？
- 受影响文档是否已更新正文（含图内文字）？
- 是否已在受影响文档的变更记录里追加条目（配合 doc-versioning）？
