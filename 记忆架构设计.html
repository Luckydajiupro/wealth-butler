1. 为什么要设计记忆架构

1.1 从人类的记忆说起

在开始设计 AI Agent 的记忆系统之前，我们先从一个每个人都在用的系统入手——人类自己的记忆。

?? 思考问题

请你回忆一下：当你的好朋友告诉你"我最近在学 Python"，你大脑中发生了什么？

  • 几秒后——你的"短期记忆"里还留着这句话，可以立刻追问"学到什么程度了？"
  • 几天后——你可能记得"他最近在学编程"，但记不清具体是 Python 还是 JavaScript
  • 几个月后——如果这个话题再也没出现过，你可能完全忘记这件事
  • 但如果他反复提起——这个信息就会被"巩固"，变成你对他长期认知的一部分："他对编程感兴趣"

这就是人类记忆的三个核心特性，也是我们设计 AI Agent 记忆架构的基础：

特性人类记忆AI Agent 映射技术实现
短期保持工作记忆（几秒到几分钟）会话上下文Redis · 30分钟TTL
中期巩固反复激活的记忆变牢固用户画像 / 偏好标签MySQL + Redis 缓存
长期遗忘不用的记忆逐渐模糊知识库 / 历史经验向量Milvus + 时间衰减

1.2 AI Agent 为什么需要记忆？

想象一个没有记忆的 AI Agent——每次对话对它来说都是"第一次见面"：

伪代码
# ? 没有记忆的 Agent
用户: "我喜欢稳健型理财"
Agent: "好的！我记下了。"

# 第二天
用户: "有什么适合我的产品？"
Agent: "请问您的风险偏好是什么？"
# → 用户会觉得很蠢——"我昨天不是说了吗？"
伪代码
# ? 有记忆的 Agent
用户: "我喜欢稳健型理财"
→ 系统提取观点: {tag: "risk_preference=稳健型", confidence: 0.6, source: "AI对话"}
→ 存入中期记忆

# 第二天
用户: "有什么适合我的产品？"
→ 系统召回记忆: "用户偏好稳健型理财 (confidence=0.55, 衰减后)"
Agent: "基于您稳健型的偏好，我推荐以下R1-R2级产品..."
# → 用户觉得很智能

?? 核心观点：记忆不是"存储聊天记录"，而是从交互中提炼有价值的信息，在合适的时机召回它。记忆架构的本质是信息的提取 → 存储 → 衰减 → 召回闭环。

1.3 三层记忆模型总览

在金融 Agent 项目中，我们设计的是"三层记忆"架构。下面这张图展示数据如何在三层之间流动：

flowchart TD subgraph 输入 A[用户对话 / 行为数据 / 交易记录] end subgraph 短期记忆层 B1[Redis 会话上下文] B2[Token 预算 · 30min TTL] end subgraph 提炼引擎 C1[客观事实提取] C2[主观观点提炼] C3[置信度计算] end subgraph 中期记忆层 D1[MySQL 画像标签] D2[Redis 热缓存] end subgraph 长期记忆层 E1[Milvus 向量库 · 经验] E2[Neo4j 图谱 · 关系] E3[MinIO 原始文档] end subgraph 遗忘机制 F1[时间衰减] F2[低置信淘汰] F3[冲突合并] end A --> B1 B1 --> B2 B2 --> C1 B2 --> C2 C1 --> C3 C2 --> C3 C3 --> D1 D1 --> D2 D2 --> E1 D2 --> E2 F1 --> D1 F2 --> D1 F3 --> D1

设计要点：不要一上来就写代码。先让学生理解——为什么是"三层"而不是一层？答案很简单：不同价值的信息，应该用不同的存储策略。就像你不会把购物小票和房产证放在同一个抽屉里。

2. 核心问题一：主观观点与客观事实的区分

2.1 什么是主观？什么是客观？

这是记忆架构设计中最容易被忽略、但最重要的问题。让我们通过例子来建立直觉：

原始对话类型说明
"我今年35岁"客观事实可验证的确定性陈述
"我觉得债券基金风险不高"主观观点个人感受，因人而异
"昨天我买了10万元的基金"客观事实交易行为，有系统记录可查
"我看好新能源板块"主观观点投资偏好判断
"我的风险等级是C3"客观事实风评结果，系统有记录
"我认为稳健型产品收益太低"主观观点态度表达，不是事实

?? 判定规则：如何区分主客观？

可以通过以下三个问题判断来判断一条信息是主观还是客观：

  1. 能否被系统验证？——能查数据库/交易记录确认的 → 客观
  2. 换一个人说是否不同？——不同人说可能不同的 → 主观
  3. 是否是情感/态度/偏好表达？——是 → 主观

?? 常见误区

常见误区：把用户的"观点"当作"事实"存入记忆。

比如用户说"我觉得基金都不好"，如果直接存入标签 user.believes: "基金不好"，系统会把它当作用户的固定属性，影响后续推荐。但实际上，这可能只是用户某一时的情绪表达。

正确做法：存为观点（opinion），附上置信度，并允许随时间衰减和修正。

2.3 代码实现思路

python · 伪代码
from dataclasses import dataclass
from enum import Enum

class InfoType(Enum):
    FACT = "fact"      # 客观事实
    OPINION = "opinion" # 主观观点

@dataclass
class ExtractedInfo:
    info_type: InfoType
    content: str            # 提取的内容
    source: str             # 来源：AI对话 / 用户自述 / 系统记录
    confidence: float       # 初始置信度
    timestamp: str
    reasoning: str          # LLM 的判定理由（用于调试）

def classify_and_extract(text: str, source: str = "AI对话") -> ExtractedInfo:
    """通过 LLM 将用户输入分类为事实或观点，并提取结构化信息"""
    result = llm.chat(
        system=SYSTEM_PROMPT,
        user=text
    )
    parsed = json.loads(result)

    # 客观事实：来源可信时直接赋予高置信度
    if parsed["type"] == "fact":
        base_confidence = 0.9 if source == "系统记录" else 0.7
    # 主观观点：初始置信度较低，需多次验证才能提升
    else:
        base_confidence = 0.5 if source == "AI对话" else 0.4

    return ExtractedInfo(
        info_type=InfoType(parsed["type"]),
        content=parsed["extracted_info"],
        source=source,
        confidence=base_confidence,
        timestamp=now(),
        reasoning=parsed["reasoning"]
    )

class OpinionExtractor:
    """从对话和行为数据中提炼观点"""

    # 从行为数据推断观点的映射表
    BEHAVIOR_TO_OPINION = {
        "频繁查看某产品净值": "对{product}有较高关注",
        "连续赎回同一类产品": "可能对{product_type}失去信心",
        "风评得分逐年上升": "风险承受能力在提升",
        "多次咨询养老产品": "可能有养老规划需求",
    }

    def extract_from_dialogue(self, dialogue: str) -> list[Opinion]:
        """从对话中提取观点"""
        # 使用 LLM 进行信息抽取
        prompt = f"""
        从以下对话中提取用户的观点。
        要求：
        1. 区分"客观事实"和"主观观点"
        2. 将观点转化为结构化标签
        3. 评估初始置信度

        对话内容：
        {dialogue}

        输出 JSON 列表：
        [{{"tag": "...", "type": "fact|opinion", "confidence": 0.X, "evidence": "原文"}}]
        """
        result = llm.chat(system=EXTRACTION_PROMPT, user=prompt)
        return [Opinion(**item) for item in json.loads(result)]

    def extract_from_behavior(self, behavior: dict) -> list[Opinion]:
        """从行为数据中推断观点"""
        opinions = []
        for pattern, template in self.BEHAVIOR_TO_OPINION.items():
            if self._match_pattern(behavior, pattern):
                opinion_text = template.format(**behavior)
                # 行为数据的观点初始置信度较高（因为有实际行为支撑）
                opinions.append(Opinion(
                    tag=opinion_text,
                    type="opinion",
                    confidence=0.7,  # 行为推导 > 口头表达
                    source="行为推断",
                    evidence=behavior
                ))
        return opinions

    def deduplicate_and_merge(self, new_opinions: list[Opinion],
                               existing: list[Opinion]) -> list[Opinion]:
        """观点去重：如果语义相似，则合并并增加证据计数"""
        merged = existing.copy()
        for new_op in new_opinions:
            # 使用向量相似度判断是否为同一观点
            similar = self._find_similar(new_op, merged)
            if similar:
                similar.evidence_count += 1
                similar.confidence = self._recalculate_confidence(similar)
            else:
                merged.append(new_op)
        return merged

?? 深度思考

思考一个问题：如果一个用户今天说"我喜欢高风险产品"，明天又说"高风险太吓人了"，系统该怎么办？

引导方向：

  • 两条都是主观观点，但可能都是"真实"的（人的偏好会变）
  • 不应该简单地覆盖，也不应该无限制累积
  • 解决方案：观点带时间戳和置信度，新的证据提升新的置信度，旧的随时间衰减
  • 如果两条矛盾 → 记录冲突计数，降低双方的置信度

4. 核心问题三：置信度机制

4.1 为什么需要置信度？

记忆中的每一条信息不是同等可靠的。置信度回答的问题是：我该在多大程度上相信这条记忆？

信息来源初始置信度为什么
风评问卷（结构化答题）0.9用户认真作答，16道题结构化打分
交易行为数据0.8行为比语言更真实
AI 从对话中提取0.6LLM 可能误解读，但有一定上下文
用户自述（直接说"我是..."）0.4用户可能随口一说，缺乏验证
系统默认值0.2纯猜测，仅作为占位

4.2 置信度的计算因子

置信度不是静态的。它会随着时间、证据、冲突而变化。设计一个置信度计算需要考虑以下因子：

flowchart LR A["来源初始值
0.2~0.9"] --> B["证据增益
+0.05/次，上限+0.3"] B --> C["冲突惩罚
-0.1/次"] C --> D["时间衰减
每年-20%"] D --> E["综合得分

class ConfidenceCalculator:
    """置信度计算引擎"""

    # 不同来源的初始置信度
    SOURCE_INITIAL = {
        "风评问卷":   0.90,
        "行为推断":   0.80,
        "AI对话提取": 0.60,
        "用户自述":   0.40,
        "系统默认":   0.20,
    }

    # 计算参数（可调）
    GAIN_PER_EVIDENCE = 0.05    # 每条证据增益
    MAX_GAIN = 0.30             # 最大增益上限
    PENALTY_PER_CONFLICT = 0.10 # 每次冲突惩罚
    ANNUAL_DECAY_RATE = 0.20    # 年衰减率（20%）

    def calc(self, source: str, evidence_count: int = 0,
             conflict_count: int = 0, age_days: int = 0) -> float:
        """计算单条记忆的置信度"""
        # 1. 来源初始值
        base = self.SOURCE_INITIAL.get(source, 0.20)

        # 2. 证据累积增益（边际递减）
        gain = min(evidence_count * self.GAIN_PER_EVIDENCE, self.MAX_GAIN)

        # 3. 冲突惩罚
        penalty = conflict_count * self.PENALTY_PER_CONFLICT

        # 4. 时间衰减（线性衰减，也可改为指数衰减）
        decay = max(0.0, 1.0 - (age_days / 365.0) * self.ANNUAL_DECAY_RATE)

        # 5. 综合计算
        score = (base + gain - penalty) * decay

        # 6. 钳制到 [0, 1]
        return max(0.0, min(1.0, score))

    def calc_timeliness(self, age_days: int) -> float:
        """计算时效性分数（用于综合重排）"""
        # 指数衰减比线性衰减更符合"记忆衰退"直觉
        import math
        half_life = 180  # 半年半衰期
        return math.exp(-age_days / half_life)

    def batch_calc(self, memory_units: list) -> list:
        """批量计算并更新所有记忆单元的置信度"""
        for unit in memory_units:
            unit.confidence = self.calc(
                source=unit.source,
                evidence_count=unit.evidence_count,
                conflict_count=unit.conflict_count,
                age_days=unit.age_days
            )
        return memory_units

?? 注意：置信度计算中的参数（初始值、增益、衰减率）都是超参数，需要根据实际业务效果调整。不要直接照搬参数，应先理解"为什么要这样设置"。

5. 核心问题四：遗忘机制

5.1 人类遗忘的启示

人类大脑每天都会遗忘大量信息——这不是缺陷，而是一种信息筛选机制。如果不遗忘，大脑会被无用信息淹没。

AI Agent 面临同样的问题：如果所有对话记录都永久保存，记忆库会无限膨胀，检索会越来越慢，质量越来越差。

?? 艾宾浩斯遗忘曲线

德国心理学家艾宾浩斯发现：遗忘的速度是先快后慢的。

  • 20分钟后：保留58%
  • 1小时后：保留44%
  • 1天后：保留33%
  • 1个月后：保留21%

启示：AI Agent 的遗忘机制也应该采用"先快后慢"的策略——新信息如果没有被反复验证，快速衰减；被验证过的信息，缓慢衰减。

5.2 机器遗忘策略

机器遗忘不是"全部删除"，而是分层处理：

flowchart TD A[记忆单元] --> B{置信度 > 阈值?} B -->|是, confidence ≥ 0.7| C["🟢 保留
进入长期记忆"] B -->|否| D{置信度 > 最低线?} D -->|是, 0.3 ≤ conf < 0.7| E["🟢 降权

保留但少召回"] D -->|否, conf < 0.3| F{是否超过最长存活期?} F -->|是, > 180天| G["🟢 淘汰

class ForgettingMechanism:
    """遗忘机制实现"""

    # 策略参数
    CONFIDENCE_KEEP_THRESHOLD = 0.70      # 保留阈值
    CONFIDENCE_DEMOTE_THRESHOLD = 0.30    # 降权阈值
    MAX_AGE_DAYS_KEEP = 180               # 最长保留天数
    MAX_AGE_DAYS_DEMOTE = 90              # 降权后最长存活天数
    CHECK_INTERVAL_DAYS = 7               # 复检周期（每周一次）

    def run_forgetting_cycle(self, memories: list[MemoryUnit]) -> dict:
        """执行一次遗忘周期——每周定期执行"""
        results = {"kept": 0, "demoted": 0, "archived": 0, "deleted": 0}

        for mem in memories:
            # 1. 更新置信度（时间衰减）
            mem.confidence = self.confidence_calc.calc(
                source=mem.source,
                evidence_count=mem.evidence_count,
                conflict_count=mem.conflict_count,
                age_days=mem.age_days
            )

            # 2. 根据置信度和年龄决定命运
            if mem.confidence >= self.CONFIDENCE_KEEP_THRESHOLD:
                # 高置信度 → 保留
                mem.status = "active"
                results["kept"] += 1

            elif mem.confidence >= self.CONFIDENCE_DEMOTE_THRESHOLD:
                # 中等置信度 → 降权
                mem.status = "demoted"
                mem.demoted_at = now()
                results["demoted"] += 1

            else:
                # 低置信度 → 检查是否超过最长存活期
                if mem.age_days > self.MAX_AGE_DAYS_KEEP:
                    if mem.age_days > self.MAX_AGE_DAYS_KEEP + 90:
                        # 超过超长期 → 永久删除
                        self.memory_store.delete(mem.id)
                        results["deleted"] += 1
                    else:
                        # 先移入归档
                        mem.status = "archived"
                        self.archive_store.move(mem)
                        results["archived"] += 1
                else:
                    # 还没到删除时间，继续观察
                    mem.status = "watching"

        self._log_cycle_results(results)
        return results

    def detect_contradictions(self, memories: list[MemoryUnit]) -> list:
        """检测矛盾观点并增加冲突计数"""
        contradictions = []
        for i, m1 in enumerate(memories):
            for m2 in memories[i+1:]:
                if m1.tag_type == m2.tag_type == "opinion":
                    if self._is_contradictory(m1, m2):
                        m1.conflict_count += 1
                        m2.conflict_count += 1
                        contradictions.append((m1, m2))
        return contradictions

class MemoryUnit:
    """记忆单元 — 记忆架构的基本组成单位"""

6.3 主流程编排伪代码

将上述所有组件串联起来，形成完整的记忆处理流程：

python · 主流程编排
class MemoryOrchestrator:
    """记忆编排器 — 串联所有记忆组件"""

    def __init__(self):
        self.extractor = OpinionExtractor()
        self.classifier = SubjectiveObjectiveClassifier()
        self.confidence = ConfidenceCalculator()
        self.validator = MemoryUnitValidator()
        self.forgetting = ForgettingMechanism()
        self.store = MemoryStore()  # 底层: Redis + MySQL + Milvus

    def process_dialogue(self, customer_id: str, dialogue: str):
        """处理一段对话，完成从提取到入库的完整流程"""
        # Step 1: 主客观分类
        classified = self.classifier.classify(dialogue)

        # Step 2: 信息提取
        if classified.type == InfoType.FACT:
            new_units = self.extractor.extract_facts(dialogue)
        else:
            new_units = self.extractor.extract_opinions(dialogue)

        # Step 3: 加载已有记忆
        existing = self.store.get_memories(customer_id, status="active")

        # Step 4: 矛盾检测
        contradictions = self.forgetting.detect_contradictions(
            new_units + existing
        )

        # Step 5: 计算置信度
        for unit in new_units:
            unit.confidence = self.confidence.calc(
                source=unit.source,
                evidence_count=unit.evidence_count,
                conflict_count=unit.conflict_count,
                age_days=0  # 新记忆
            )

        # Step 6: 校验 & 入库
        for unit in new_units:
            result = self.validator.validate(unit)
            if result["valid"]:
                self.store.save(unit)
            else:
                logger.warning(f"记忆校验失败: {result['errors']}")

        # Step 7: 短期记忆同步写入 Redis（会话上下文）
        self.store.save_to_short_term(customer_id, dialogue)

    def recall_memories(self, customer_id: str, scenario: str,
                        query: str = None, top_k: int = 5) -> list[MemoryUnit]:
        """根据场景召回相关记忆"""
        # 1. 从存储层检索（Milvus 向量检索 + MySQL 精确查询）
        candidates = self.store.search(customer_id, query, limit=top_k * 3)

        # 2. 更新召回计数
        for mem in candidates:
            mem.recall_count += 1
            mem.last_recall_time = now()

        # 3. 综合重排（置信度 + 语义相关性 + 场景权重 + 时效性）
        ranked = self.confidence.rank(candidates, scenario)

        # 4. 返回 TopK
        return ranked[:top_k]

    def run_weekly_maintenance(self):
        """每周维护任务：置信度重算 + 遗忘周期 + 矛盾检测"""
        all_memories = self.store.get_all_active()

        # 1. 检测矛盾
        contradictions = self.forgetting.detect_contradictions(all_memories)

        # 2. 置信度重算（时间衰减）
        self.confidence.batch_calc(all_memories)

        # 3. 遗忘周期
        results = self.forgetting.run_forgetting_cycle(all_memories)

        # 4. 更新存储
        for mem in all_memories:
            self.store.update(mem)

        logger.info(f"维护完成: {results}")

7.2 开放性思考

以下问题没有标准答案，旨在激发深度思考：

思考一：记忆与隐私

如果用户说"请忘记我说过的话"，系统应该如何执行"被遗忘权"？

  • 直接删除所有记忆？
  • 只删除主观观点，保留客观事实？
  • 将置信度置为0但保留记录（用于审计）？

提示：这涉及GDPR/个人信息保护法合规要求。金融场景下，交易记录等行为数据有法定保存期限，不能随意删除。

思考二：记忆的"元认知"

人类不仅有记忆，还有"对自己记忆的认知"——我们知道"我记得不太清楚"。AI Agent 能否做到类似的事？

可能的方向：

  • 当置信度低于某个阈值时，Agent 主动说"我可能记不太清了，您能确认一下吗？"
  • 当记忆之间矛盾较多时，Agent 能意识到"我对这个用户的了解还不够一致"
  • 当长期没有新证据时，Agent 能判断"这条记忆可能已经过时了"

思考三：多用户记忆的关联

在金融场景中，一个理财顾问可能服务多个客户。记忆架构能否在用户之间建立"元记忆"？

  • 理财顾问的 Agent 是否能记住"客户A和客户B都关注新能源板块"？
  • 当客户A买了某产品后，Agent 是否能联想到"客户B可能也感兴趣"？
  • 这种跨用户记忆的边界和隐私保护如何设计？

思考四：设计更复杂的记忆架构

在现有的三层记忆基础上，还可以扩展哪些层次？

可能的扩展层说明类比人类
程序性记忆记住"怎么做"——用户常用的操作流程、偏好界面等骑自行车（肌肉记忆）
情景记忆记住"在什么场景下说过什么"——带完整上下文的事件记录第一次见面
语义记忆提炼出的通用知识——"这类客户通常偏好X"百科知识
元记忆关于记忆的记忆——"我知道我记不清了"记忆力自我评估

挑战：试着为其中一层设计数据结构、存储策略和遗忘规则。
