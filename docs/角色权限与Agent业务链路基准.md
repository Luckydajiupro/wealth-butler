# 智能财富管家系统：角色权限与 Agent 业务链路基准

**文档状态**：当前基准口径  
**适用范围**：角色工作台、Agent 分工、客户业务链路、工单流转与 Redis Stream 结果回传  
**安全声明**：本文档只定义系统行为约束，不执行数据库、向量库、Redis 数据或真实交易变更。

## 1. 员工角色

系统员工只允许以下四类：

- 理财顾问
- 客户经理
- 风控专员
- 业务管理员

每个员工登录后只能进入与其角色对应的工作台，不能通过修改 URL 访问其他角色页面。后端必须再次校验角色，前端路由和页面隐藏不能替代授权。

## 2. 员工权限

### 2.1 理财顾问

**工作台**：`/chat/advisor`

负责：

- 查看自己负责的客户；
- 查看客户四维画像、风险等级、持仓和交易概览；
- 查看产品库详情；
- 生成产品推荐；
- 生成资产配置方案；
- 说明推荐和配置理由；
- 进行适当性分析和组合诊断。

不负责：

- 申购执行；
- 赎回执行；
- 转账执行；
- 可疑交易处置；
- 风险规则配置。

### 2.2 客户经理

**工作台**：`/chat/operator`

负责：

- 只能办理自己已领取或负责的客户；
- 申购；
- 追加申购；
- 赎回；
- 转账；
- 账户资料变更；
- 客户业务工单领取、核验、办理和跟踪；
- 必要时提交可疑交易上报。

不负责：

- 产品推荐决策；
- 资产配置结论；
- 风险规则配置；
- 风险预警领取和裁决；
- 全量客户管理。

### 2.3 风控专员

**工作台**：`/chat/risk`

负责：

- 风险预警；
- 可疑交易；
- 大额交易；
- 异常行为调查；
- 风险规则配置；
- 风险预警详情；
- 补充调查材料；
- 风险处置结论；
- 风险报表。

不负责：

- 客户申购；
- 客户赎回；
- 客户转账；
- 普通客户资料维护；
- 产品推荐。

### 2.4 业务管理员

**工作台**：管理员/分析工作台。

负责：

- 全量客户和工单查看；
- 员工权限和角色管理；
- 全量业务监督；
- 风险和经营报表；
- 系统配置；
- 必要的复核和授权。

业务管理员可以查看全部数据，但不应替代专业角色完成所有业务操作。

## 3. Agent 职责

### 3.1 客服 Agent

面向客户，负责：

- 回答产品、费用、风险等级、期限、规则和账户基础问题；
- 查询客户自己的持仓、交易和收益；
- 识别客户意图；
- 对申购、追加申购、赎回、转账追问必要信息；
- 信息完整后创建对应业务工单；
- 将推荐需求转交投顾 Agent；
- 将执行需求转交客户经理；
- 将异常交易转交风控 Agent。

普通知识问题应直接回答，不应创建工单。

客服 Agent 不执行申购、赎回、转账、资料变更等资金或账户写操作。

### 3.2 投顾 Agent

负责：

- 客户风险和画像分析；
- 产品推荐；
- 资产配置；
- 组合诊断；
- 适当性判断；
- 配置理由和风险说明。

投顾 Agent 不执行申购、赎回和转账。

### 3.3 客户经理/运营 Agent

负责：

- 客户业务工单识别；
- 产品、金额、账户和资料核验；
- 申购、追加申购、赎回、转账和资料变更的业务草稿；
- 二次确认；
- mock 账户、余额、持仓和交易记录变动；
- 将业务结果写入工单和交易记录。

### 3.4 风控 Agent

负责：

- 风险规则命中；
- 大额交易和异常行为识别；
- 可疑交易分析；
- 风险预警调查；
- 风险等级和处置建议；
- 规则配置和报表。

### 3.5 分析 Agent

负责：

- 经营数据；
- 客户和交易统计；
- 产品销售分析；
- 风险趋势；
- 工单处理效率；
- 管理员数据报表。

## 4. 业务链路

### 4.1 普通知识问答

```text
客户 → 客服 Agent → 向量库/产品库 → 直接回答
```

例如风险等级、费率、期限等问题，直接返回知识库或产品库结果，不应自动创建工单，也不应自动弹出风险测评。

### 4.2 产品推荐

```text
客户 → 客服 Agent → 投顾 Agent
      → 查询画像、风险等级、持仓、产品库
      → 推荐产品和配置方案
      → 客户确认
      → 如需执行，再转客户经理
```

投顾 Agent 只生成推荐、配置和说明，不执行交易。

### 4.3 申购

```text
客户 → 客服 Agent 追问产品、金额、账户和风险确认
      → 创建申购工单
      → 客户经理领取
      → 资料和适当性核验
      → 生成业务草稿
      → 客户二次确认
      → mock 扣减可用资金、增加持仓、写交易记录
      → Redis Stream 回传结果
      → 客服 Agent 回复客户
```

### 4.4 追加申购

```text
客户 → 客服 Agent 根据持仓识别产品
      → 追问追加金额和付款账户
      → 创建追加申购工单
      → 客户经理办理
      → 客户二次确认
      → mock 更新余额、持仓和交易记录
      → Redis Stream 回传结果
      → 客服 Agent 回复客户
```

追加申购必须使用明确的工单子类型，不能仅以模糊的“客户转介”代替。

### 4.5 赎回

```text
客户 → 客服 Agent 识别持仓产品
      → 追问赎回份额或比例、到账账户
      → 创建赎回工单
      → 客户经理核验
      → 客户确认
      → 减少持仓、增加可用资金、写交易记录
      → Redis Stream 回传结果
      → 客服 Agent 回复客户
```

### 4.6 转账

```text
客户 → 客服 Agent 追问金额、转出账户、收款账户和用途
      → 创建转账工单
      → 客户经理核对收款人
      → 风控规则检查
      → 必要时转风控
      → 客户确认
      → mock 扣减余额并写流水
      → Redis Stream 回传结果
      → 客服 Agent 回复客户
```

### 4.7 资料变更

```text
客户 → 客服 Agent 追问变更字段和必要身份信息
      → 创建资料变更工单
      → 客户经理核验资料
      → 客户确认
      → mock 更新账户资料并写操作记录
      → Redis Stream 回传结果
      → 客服 Agent 回复客户
```

### 4.8 风险预警

```text
交易或行为触发规则
      → 风控 Agent 创建风险预警
      → 风控专员领取
      → 调查交易、客户和命中规则
      → 标记处理中
      → 提交风险处置结论
      → 必要时业务管理员复核
```

客户经理只能提交可疑交易上报或查看转交状态，不能领取和处理风险预警。

### 4.9 风险测评

```text
客户登录
      → 检查是否完成风险测评
      → 未测评或已过期则引导测评
      → 完成测评
      → 生成风险等级和有效期
      → 同步画像和产品适配范围
```

只有客户主动进入测评流程或测评过期时才显示问卷。普通知识问答、普通客服聊天和普通业务咨询不应自动弹出测评问卷。

### 4.10 数据分析

```text
业务数据和工单数据
      → 分析 Agent 汇总统计
      → 生成经营、销售、风险和工单效率报表
      → 业务管理员在管理员/分析工作台查看
```

## 5. 工单对应关系

| 工单类型 | 处理角色 |
|---|---|
| 产品推荐 | 理财顾问 |
| 配置方案 | 理财顾问 |
| 组合诊断 | 理财顾问 |
| 适当性复核 | 理财顾问 |
| 申购 | 客户经理 |
| 追加申购 | 客户经理 |
| 赎回 | 客户经理 |
| 转账 | 客户经理 |
| 资料变更 | 客户经理 |
| 可疑交易 | 风控专员 |
| 大额交易预警 | 风控专员 |
| 风险规则命中复核 | 风控专员 |
| 数据报表 | 业务管理员 / 分析 Agent |
| 权限配置 | 业务管理员 |

“客户转介”不能作为模糊业务类型，必须同时带有具体业务子类型，例如：

- 客户转介 + 申购；
- 客户转介 + 赎回；
- 客户转介 + 资料变更；
- 客户转介 + 产品配置；
- 客户转介 + 风险预警。

工单至少应能区分 `order_type` 和具体业务子类型，并保留客户对象、创建来源、处理角色、处理人、状态和审计信息。

## 6. Redis Stream 回传

专业 Agent 或员工处理业务后，按以下链路回传客户会话：

```text
专业 Agent 或员工处理
      → 写入业务结果
      → Redis Stream 发布结果事件
      → 客服 Agent 消费事件
      → 按 customer_id 绑定客户会话
      → 校验事件与工单的对应关系
      → 向客户展示处理结果
```

结果事件至少应能定位：

- 客户 `customer_id`；
- 对应工单及具体业务子类型；
- 业务结果状态；
- 结果摘要；
- 事件时间；
- 请求或处理追踪标识。

Redis Stream 只负责可靠传递结果事件，不替代业务结果记录。余额、持仓、交易记录、工单状态和风险处置记录必须先完成对应写入，再发布结果事件。客服 Agent 消费事件后，应将结果绑定到正确客户会话，不能把其他客户或其他工单的结果混入当前会话。

## 7. 强制约束

- 前端入口必须与角色权限一致；
- 后端必须进行角色和对象级客户权限校验；
- 每个员工登录后只能进入其角色工作台，修改 URL 不得访问其他角色页面；
- 理财顾问只能查看自己负责的客户；
- 客户经理只能操作自己领取或负责的客户；
- 业务管理员可以查看全部数据，但不应替代专业角色完成所有业务操作；
- 风控工单不能出现在客户经理待办池；
- 投顾工单不能出现在客户经理事务池；
- 客户经理不能领取和处理风险预警；
- 所有资金业务必须二次确认；
- mock 交易必须同步更新余额、持仓和交易记录；
- Redis Stream 事件必须绑定正确的客户、工单和业务子类型；
- 风险处置必须保留操作人、时间、规则和审计记录；
- 所有角色页面的“查看详情”“规则配置”“数据报表”必须可用，不能只有静态文字；
- 工单状态必须按角色限制，不允许跨角色领取或处理；
- 普通知识问题直接回答，不应自动创建工单；
- 普通知识问答和普通业务咨询不应自动弹出风险测评；
- 客服 Agent 不执行资金和账户写操作；
- 投顾 Agent 不执行申购、赎回和转账；
- 风控专员负责风险预警领取、调查和处置，客户经理仅能提交可疑交易上报或查看转交状态；
- 业务管理员可以复核和授权，但不能以管理员身份绕过专业角色职责、二次确认或审计要求。
