# 数据层建表指南

## 前置条件

### 1. 配置数据库连接

复制 `.env.example` 为 `.env`，填写数据库连接信息：

```bash
cp .env.example .env
```

编辑 `.env` 文件：

```ini
# MySQL配置
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your_password
MYSQL_DATABASE=wealth_butler

# Milvus配置
MILVUS_HOST=localhost
MILVUS_PORT=19530

# Neo4j配置
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password

# Ollama Embedding配置（用于Milvus向量化）
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_EMBEDDING_MODEL=bge-m3
```

### 2. 启动数据库服务

确保以下服务已启动：
- MySQL 8.0+
- Milvus 2.3+
- Neo4j 5.0+
- Ollama（本地Embedding服务）

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

## 执行建表

### 方式一：统一建表脚本（推荐）

```bash
python scripts/init_data_layer.py
```

该脚本会依次创建：
- MySQL 10张业务表（含base_user扩展字段）
- Milvus 4个向量集合
- Neo4j图谱schema（节点/关系/索引/约束）

### 方式二：分步执行

#### MySQL建表

```python
from app.WealthButler.Models.customerProfileModel import CustomerProfileModel

# Model类首次使用时会自动调用_ensure_table_exists()创建表
CustomerProfileModel._ensure_table_exists()
```

#### Milvus集合创建

```python
from app.WealthButler.Repository.faqCollectionModel import FaqCollectionModel

# 实例化时会自动调用_check_and_create_collection()创建集合
FaqCollectionModel._check_and_create_collection()
```

#### Neo4j schema初始化

```python
from app.WealthButler.Knowledge.graphSchema import Neo4jGraphSchema
from app.Base.Client.neo4jClient import get_neo4j_client

neo4j_client = get_neo4j_client()
for cypher in Neo4jGraphSchema.get_init_cypher_list():
    neo4j_client.run(cypher)
```

### Milvus集合（4个）

| 集合名 | 说明 | 检索策略 | Model文件 |

### Neo4j图谱

**节点类型（6种）**
- Customer（客户）
- Product（产品）
- RiskLevel（风险等级：C1-C5/R1-R5）
- Industry（行业）
- Market（市场）
- FundManager（基金管理人）

**关系类型（7种）**
- HAS_RISK_LEVEL：客户→风险等级
- INVESTS_IN：客户→产品（持仓）
- BELONGS_TO：产品→行业
- MANAGED_BY：产品→基金管理人
- SUITABLE_FOR：产品→风险等级（适当性匹配）
- LOCATED_IN：行业→市场
- RELATED_TO：客户→客户（关联账户）

## 常见问题

### Q: MySQL建表失败，提示"表已存在"

A: 脚手架的`_ensure_table_exists()`会自动检查表是否存在，如果已存在则跳过创建。这是正常行为。

### Q: Milvus连接失败

A: 检查Milvus服务是否启动，端口是否正确（默认19530）。

### Q: Neo4j约束创建失败

A: 如果约束已存在会报错，可以先删除旧约束：
```cypher
DROP CONSTRAINT customer_id_unique IF EXISTS
```

### Q: base_user扩展字段未添加

A: 需要手动执行ALTER TABLE语句，或运行`scripts/init_data_layer.py`脚本。
