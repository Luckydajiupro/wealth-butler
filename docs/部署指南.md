# 智能财富管家系统 - 部署指南

## 1. 环境要求

### 1.1 运行环境
- **Python版本**：Python 3.10+
- **操作系统**：Windows 10/11、Linux、macOS

### 1.2 数据库与中间件
- **MySQL**：5.7+ 或 8.0+（推荐8.0）
- **Redis**：5.0+（用于事件总线和缓存）
- **Milvus**：2.0+（向量数据库，用于RAG知识库检索）
- **Neo4j**：5.0+（图数据库，用于投顾知识图谱）
- **MinIO**：用于对象存储（可选，存储知识库原始文件）

### 1.3 大模型服务
- **通义千问**：需要阿里云DashScope API Key
- **Ollama**：本地向量模型服务（使用bge-m3模型）
- **DeepSeek**：用于数据分析（可选）

## 3. 数据库配置

### 3.1 创建数据库
```sql
CREATE DATABASE wealth_butler CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3.2 执行建表脚本
系统采用代码优先（Code First）方式，表结构由Model层自动创建。首次启动时会自动检测并创建所需表。

**核心数据表**：
- `base_user` - 用户表（含客户和员工）
- `fin_customer_profile` - 客户画像表
- `fin_product` - 产品表
- `fin_transaction` - 交易流水表
- `fin_holdings` - 持仓表
- `fin_risk_alert` - 风险预警表
- `biz_work_order` - 业务工单表
- `fin_conversation_archive` - 会话归档表
- `fin_knowledge_meta` - 知识库元数据表

### 3.3 初始化Mock数据
```bash

# 导入数据库
```

**Mock数据内容**：

- 11款本司产品 + 5款其他公司产品

## 7. 常见问题排查

### 7.1 数据库连接失败
**症状**：启动时报错 `Database connection failed`

**解决方法**：
1. 检查MySQL服务是否启动
2. 验证`.env`中的数据库配置（主机、端口、用户名、密码）
3. 确认数据库`wealth_butler`已创建
4. 测试连接：`mysql -h 127.0.0.1 -u root -p`

### 7.2 Redis连接失败
**症状**：启动时报错 `Redis connection failed`

**解决方法**：
1. 检查Redis服务是否启动：`redis-cli ping`（应返回PONG）
2. 验证`.env`中的Redis配置
3. Windows用户：确认Redis服务已安装并启动

### 7.3 Milvus连接失败
**症状**：RAG检索功能不可用

**解决方法**：
1. 检查Milvus服务状态
2. 验证`MILVUS_URI`配置
3. 确认向量维度配置：`MILVUS_VECTOR_DIM=1024`（与bge-m3模型匹配）

### 7.4 Ollama模型未加载
**症状**：RAG检索报错 `Embedding model not found`

**解决方法**：
```bash
# 拉取bge-m3模型
ollama pull bge-m3

# 验证模型已安装
ollama list
```

### 7.5 JWT认证失败
**症状**：登录后接口返回401 Unauthorized

**解决方法**：
1. 检查`.env`中的`JWT_SECRET`是否配置
2. 清除浏览器缓存和LocalStorage
3. 重新登录获取新Token

### 7.6 端口占用
**症状**：启动时报错 `Address already in use`

**解决方法**：
```bash
# 查找占用8010端口的进程
netstat -ano | findstr 8010  # Windows
lsof -i :8010                # Linux/macOS

# 修改启动端口
uvicorn app.WealthButler.main:app --port 8011
```

### 7.7 导入Mock数据失败
**症状**：执行SQL文件报错

**解决方法**：
1. 确认字符集为utf8mb4：`ALTER DATABASE wealth_butler CHARACTER SET utf8mb4;`
2. 检查SQL文件编码为UTF-8
3. 分批导入：拆分SQL文件为多个小文件
