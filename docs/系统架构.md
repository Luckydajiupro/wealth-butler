# 智能财富管家系统 - 系统架构文档

## 1. 整体架构

### 1.1 架构设计理念
智能财富管家系统采用**分层架构 + Agent编排**的设计模式，核心特点：
- **复用脚手架能力**：基于Base脚手架模块（D:\lqh\reproject\ric-train\ric-train\Base），快速构建业务系统
- **Agent驱动业务**：5个AI Agent处理不同业务场景（客服、投顾、分析、操作、风控）
- **事件驱动架构**：EventBus实现模块解耦和异步处理
- **分层清晰**：严格遵循表现层→业务层→数据层的分层原则

## 4. 各模块职责

### 4.1 API接口层（Api）
**职责**：
- 接收HTTP请求，参数验证
- JWT认证和权限校验
- 调用Service层处理业务逻辑
- 封装统一响应格式（HttpResponse）
- SSE流式输出支持

**关键文件**：
- `chatApi.py` - 对话接口（统一入口 + 5个直连路由）
- `riskApi.py` - 风险预警CRUD + 处理流程
- `holdingsApi.py` - 持仓查询
- `workOrderApi.py` - 工单管理CRUD
- `frontendApi.py` - 前端页面路由

### 4.2 业务逻辑层（Service）
**职责**：
- 实现核心业务逻辑
- 编排多个数据源和外部服务
- Agent调度和结果处理
- 事件发布

**关键文件**：
- `chatService.py` - 对话服务核心（Agent路由、会话管理）
- `agentDispatch.py` - Agent分发器（根据agent_type分发）
- `workOrderService.py` - 工单业务逻辑

### 4.3 AI Agent层（Agent）
**职责**：
- 实现5个业务Agent的核心逻辑
- 继承Base脚手架的BaseAgent
- 集成Middleware栈（日志、评估、安全）
- 调用LLM和工具完成任务

**5个Agent**：
1. **CustomerAgent** - 智能客服（RAG检索 + 会话记忆）
2. **AdvisorAgent** - 投顾助手（画像分析 + 产品推荐 + GraphRAG）
3. **AnalystAgent** - 数据分析（NL2SQL + 安全校验）
4. **OperatorAgent** - 业务操作（NL2API + 二次确认）
5. **RiskAgent** - 风控监测（规则引擎 + 事件驱动）

**Agent工作流**：
```
用户输入 → Agent接收 → Middleware预处理 → LLM推理 → Tool调用 → Middleware后处理 → 返回结果
```

### 4.4 EventBus层（EventBus）
**职责**：
- 基于Redis Pub/Sub实现事件总线
- 解耦模块间依赖
- 异步处理耗时任务

**事件类型**：
- `risk:alert` - 风险预警事件（交易触发规则后发布）
- `workorder:created` - 工单创建事件
- `conversation:archived` - 会话归档事件

**工作流程**：
```
业务模块 → 发布事件(publisher.py) → Redis Pub/Sub → 消费者(consumer.py) → 处理逻辑
```

### 4.5 数据模型层（Models）
**职责**：
- 定义业务实体（继承BaseDBModel）
- ORM映射（Python对象 ↔ MySQL表）
- 提供CRUD方法和业务查询方法

**核心模型**：
- `customerProfileModel.py` - 客户画像（风险等级、资产配置、FM标记）
- `productModel.py` - 产品信息（产品编码、风险等级、净值）
- `transactionModel.py` - 交易流水（申购、赎回、转账）
- `holdingsModel.py` - 持仓信息（份额、成本、盈亏）
- `riskAlertModel.py` - 风险预警（规则ID、严重程度、处理状态）
- `workOrderModel.py` - 业务工单（类型、状态、处理人）

### 4.6 数据访问层（Repository）
**职责**：
- 封装复杂SQL查询
- 跨表关联查询
- 数据库连接池管理

**基础能力（Base脚手架提供）**：
- `BaseDBModel` - ORM基类（支持自动建表、CRUD）
- `milvusClient.py` - Milvus向量检索
- `neo4jClient.py` - Neo4j图查询
- `redisClient.py` - Redis缓存和队列

### 4.7 前端层（Frontend）
**职责**：
- 提供Web界面
- 调用后端API
- SSE流式接收对话内容

**页面列表**：
- `login.html` - 登录页
- `customer_dashboard.html` - 客户工作台（持仓查询、智能客服）
- `advisor_dashboard.html` - 理财顾问工作台（投顾助手、客户画像）
- `operator_dashboard.html` - 客户经理工作台（业务操作、工单管理）
- `risk_dashboard.html` - 风控专员工作台（风险预警列表、处理）
- `admin_dashboard.html` - 系统管理员工作台（全局视图）

## 5. 数据流向

### 5.1 对话流程（以投顾助手为例）
```
1. 用户在前端输入：推荐适合客户的产品
   ↓
2. 前端调用：POST /api/chat/advisor
   ↓
3. chatApi.py 验证JWT → 提取user_id和customer_id
   ↓
4. chatService.route_to_agent() 分发到AdvisorAgent
   ↓
5. AdvisorAgent执行：
   - 查询客户画像（customerProfileModel）
   - 查询产品列表（productModel）
   - 调用适当性规则（suitabilityRules）
   - 调用LLM生成推荐话术
   - GraphRAG增强（neo4jClient查询产品关系）
   ↓
6. 返回SSE流式输出
   ↓
7. 前端EventSource接收并渲染
```

### 5.2 风险预警流程
```
1. 客户发起大额转账（operator通过NL2API执行）
   ↓
2. transactionModel.save() 写入交易记录
   ↓
3. 触发风险规则检查（riskRules.py）
   ↓
4. 规则命中：单笔转账>5万且目标地区为高风险地区
   ↓
5. 发布风险事件：EventBus.publish("risk:alert", alert_data)
   ↓
6. RiskAgent消费事件 → 创建riskAlertModel记录
   ↓
7. 风控专员在工作台查看预警（GET /api/wealth/risk/alerts）
   ↓
8. 处理预警：PUT /api/wealth/risk/alert/{id}/handle
   - action=process（处理中）
   - action=confirm（确认风险）
   - action=mark_false（误报）
   ↓
9. 若need_override=true → 需要管理员裁决
```

### 5.3 业务操作二次确认流程
```
1. 客户经理：帮客户申购XX基金5万元
   ↓
2. POST /api/chat/operator
   ↓
3. OperatorAgent识别意图：purchase
   ↓
4. 提取参数：product_id=1, amount=50000
   ↓
5. 检查是否需要二次确认（金额>1万）
   ↓
6. 返回confirm_required响应（含confirm_token）
   ↓
7. 前端弹窗确认
   ↓
8. 用户点击确认 → POST /api/chat/operator/confirm
   ↓
9. 验证confirm_token → 执行真实业务操作
   ↓
10. 创建交易记录 → 更新持仓 → 返回成功
```

## 10. 性能优化建议

### 10.1 数据库层
- MySQL连接池：max_connections=20
- Redis连接池：max_connections=50
- 索引优化：为高频查询字段建索引

### 10.2 缓存策略
- 客户画像缓存（TTL=1小时）
- 产品列表缓存（TTL=30分钟）
- 会话历史缓存（TTL=10分钟）

### 10.3 LLM调用优化
- Prompt缓存（相同Prompt复用结果）
- 流式输出（降低首字延迟）
- 超时控制（LLM_TIMEOUT=300秒）

### 10.4 并发处理
- Uvicorn Worker数量：CPU核心数 * 2
- 数据库连接池：根据并发量调整
- Redis队列：EventBus支持多消费者
