# Phase 5 答辩 Demo 说明

## 1. 运行方式

在项目根目录执行：

```powershell
python scripts/run_phase5_demo.py
```

成功时最后一行为 `RESULT | PASS`。脚本不会打印种子密码、JWT、确认令牌或数据库凭据。

## 2. 前置条件

- `WB-SEED-20260817` 种子已完成 MySQL、Milvus、Neo4j 导入与验证。
- `.env` 已配置项目现有 MySQL、Milvus、Neo4j、本地 embedding 服务和 `WEALTH_BUTLER_SEED_PASSWORD`。
- 依赖已按项目 `requirements.txt` 安装。

## 3. 演示场景

| 顺序 | 场景 | 数据与隔离边界 | 预期结果 |
|---|---|---|---|
| 1 | 陈秀兰客户认证 | 真实密码哈希校验与 JWT 回读；不显示 token | 客户身份通过，员工权限全部拒绝 |
| 2 | C1 风险评估 | 真实 MySQL 只读 | 有效风评、完整问卷记录 |
| 3 | 反诈客服 RAG | 真实 Milvus + 本地 embedding；无外部 LLM | 召回反诈/养老保护语料 |
| 4 | 投顾 GraphRAG | 真实 Neo4j，只读确定性 Cypher | 返回持仓行业关系 |
| 5 | 适当性 | 真实 MySQL 产品与风评，只读 | C1 只放行 R1/R2，拒绝 R3+ 推荐 |
| 6 | Operator 申购二次确认 | 注入式内存事务、确认存储和事件总线 | 超过 1 万元必须确认，并发确认至多执行一次 |
| 7 | 持仓 | 真实 MySQL 只读 | 返回种子持仓，不新增或修改交易 |
| 8 | 风控预警与工单 | 真实种子关联只读；事件异常路径使用注入测试 | 预警可追溯至工单，事件失败进入重试 |
| 9 | NL2SQL | 确定性 SQL 生成器 + 真实只读执行器 | 聚合查询通过；敏感列和多语句破坏输入拒绝 |

## 4. 答辩安全口径

- Demo 不调用外部 LLM，避免网络和模型输出波动影响验收。
- 真实环境只验证认证、检索、图谱和业务只读链。
- 申购确认、事务执行和事件失败均在注入式隔离环境演示，不产生真实资金副作用。
- 任一依赖或断言失败均输出对应 `FAIL` 并以非零退出码结束，不降级伪造成功。
