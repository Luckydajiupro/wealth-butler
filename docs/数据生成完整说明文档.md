# 智能财富管家系统 - 数据生成完整说明文档

**生成日期**：2026-08-17  
**数据规模**：200名客户全链路业务数据  
**涉及数据库**：MySQL、Milvus、Neo4j、Redis、MinIO（5个）

---

## 一、项目背景

智能财富管家系统是一个多Agent协同的智能财富管理平台，包含理财顾问Agent、风控Agent、客服Agent、分析师Agent等。为了进行系统测试和演示，需要生成一套完整的、跨多个数据库的真实业务数据。

**核心要求**：
- 模拟200名真实客户的金融理财全生命周期
- 数据必须符合金融业务逻辑（风险评估、资产配置、交易流程等）
- 确保跨数据库的数据一致性（customer_id、product_id等主键对齐）
- 包含极高净值客户（资产5000万-5亿）
- 严格执行16题风险评估问卷逻辑
- 支持AI功能（RAG检索、图谱分析、客户记忆等）

---

## 二、数据架构设计

### 2.1 五大数据库分工

| 数据库 | 作用 | 典型数据 |
|--------|------|----------|
| **MySQL** | 主业务数据 | 客户、员工、产品、交易、持仓、工单、风险预警 |
| **Milvus** | 向量数据 | 客户记忆、产品知识、FAQ、政策法规（支持RAG检索） |
| **Neo4j** | 关系图谱 | 客户-顾问-产品关系、持仓关系、交易关系 |
| **Redis** | 缓存与消息 | 客户画像缓存、持仓汇总、工单通知、事件流 |
| **MinIO** | 对象存储 | 录音录像元数据、风险揭示书、合规证据索引 |

### 2.2 数据一致性设计

**主键对齐**：
- `customer_id`：MySQL base_user表的主键，同步到Neo4j节点、Milvus记录、Redis键、MinIO元数据
- `product_id`：MySQL fin_product表的主键，同步到所有相关表和集合
- `employee_id`：MySQL员工ID，同步到图谱和工单记录

**金额一致性**：
- 持仓成本 = SUM(申购金额) - SUM(赎回金额)
- MySQL `fin_holdings.cost` = Neo4j `HOLDS关系.amount`
- 所有金额计算可复算验证

**时间顺序**：
- 开户时间 < 风险评估时间 < 首次交易时间 < 持仓更新时间
- 交易记录按时间递增生成，符合业务逻辑

**评分逻辑**：

```python
# 总分 = SUM(每题分数 × 权重) × 100
# 总分范围：0-100分

C2（稳健型）：36-50分
C3（平衡型）：51-65分
C4（进取型）：66-80分
C5（激进型）：81-100分
```

**答案生成逻辑**：
根据客户属性自动生成合理答案：
- 年龄大→Q1选低风险选项
- 资产高→Q4选高资产选项
- 职业为企业家→Q5投资经验丰富
- 风险等级高→Q10、Q11选高风险承受力

**数据特点**：
- 180份评估（90%客户完成，10%未测评）
- 总分可复算（误差<0.1分）
- 风险等级与客户资产、年龄匹配

#### 3.6 交易记录数据（2041条）

**交易类型分布**：
- 申购（BUY）：60%
- 赎回（REDEEM）：30%
- 分红（DIVIDEND）：10%

**生成逻辑**：

   - 后续交易间隔5-90天
   - 交易时间递增，不会倒序
2. **金额合理性**：
   - 申购金额 = 客户总资产 × 已投资占比 / 持仓数量
   - 赎回金额 ≤ 当前持仓金额
   - 分红金额 = 持仓份额 × 分红比例
3. **产品匹配**：
   - 客户只能购买符合其风险等级的产品

   - C5客户可以买所有产品
4. **顾问关联**：
   - 每笔交易记录对应的理财顾问（employee_id）
   - 金卡客户→初级顾问、私行客户→私人银行家

**字段说明**：

- `customer_id`：客户ID
- `product_id`：产品ID
- `transaction_type`：BUY/REDEEM/DIVIDEND
- `amount`：交易金额
- `shares`：交易份额
- `nav`：交易时产品净值
- `fee`：手续费
- `status`：SUCCESS/PENDING/FAILED
- `employee_id`：经办顾问
- `created_at`：交易时间

**数据表**：`fin_transaction`

#### 3.7 持仓记录数据（1225个）

**生成逻辑**：
1. **从交易记录计算**：
   - 持仓成本 = SUM(申购金额) - SUM(赎回金额)
   - 持仓份额 = SUM(申购份额) - SUM(赎回份额)
2. **当前市值计算**：
   - 当前市值 = 持仓份额 × 产品当前净值(nav)
   - 盈亏金额 = 当前市值 - 持仓成本
   - 盈亏比例 = 盈亏金额 / 持仓成本 × 100%
3. **过滤零持仓**：
   - 如果持仓份额≤0，不生成持仓记录
   - 客户平均持仓3-4个产品

**数据特点**：
- 金额可复算：持仓成本 = 交易累计
- 与Neo4j HOLDS关系金额一致
- 每个持仓有产品快照（nav, product_name等）

**数据表**：`fin_holdings`

**预警规则**：

- RW-002：频繁交易（7天内>5笔）
- RW-003：持仓超风险等级（C1客户持有R4产品）

**生成逻辑**：

2. **从持仓触发**：
   - 持仓产品风险等级 > 客户风险等级+1 → RW-003
3. **严重级别**：
   - LOW（低）：提示性预警
   - MEDIUM（中）：需要关注
   - HIGH（高）：需要立即处理
   - CRITICAL（严重）：紧急处理
