# 开发计划

## 0. 文档说明

本文档是《答辩所需文本交付物清单.txt》要求的"开发计划"，是需求文档§8.5"开发方式与工期"、§4"功能性需求"（Phase1~5）、§9.1"验收标准"三节内容的任务分解落地版——把老师原始文档按"周"划分的Phase 1~5，压缩进团队实际的4天工期，功能范围不变，只是节奏从"周"变成"天"。

**核心节奏原则**（继承自需求文档§8.5，不是本文档另起的安排）：不严格按Phase 1→2→3→4→5串行开发，而是分成多条轨道并行开工，因为7项"无捷径、必须优先攻坚的关键路径"任务（下文标🔑）如果等到对应Phase顺序才启动会来不及，必须从Day1就投入人力。

**人员分工**：已按团队实际6人名单确认（见下表），后续如有调整以每日会议纪要记录为准，本文档不再重复确认。

## 2. Day-by-day 任务清单

## 3. 风险与应急预案

- 若🔑关键路径任务（NL2Cypher查询生成/NL2SQL全链路/记忆置信度体系/风控规则引擎/事件总线/多Agent编排/业务表+API骨架）在**Day2结束时**仍未达到可演示状态，负责人应立即记入会议纪要并向李清华报告，重新分配人力抢救，优先级高于Phase3/4的非关键功能。
- 时间实在不足时的取舍顺序（参照需求文档§9.2扣分项权重）：优先保证"项目能启动"（不启动扣分最重，-20）与"核心功能不缺失"（-10/项，尤其是《答辩须知》明确要求现场演示的RAG/GraphRAG/NL2SQL/NL2API四项，以及风控规则引擎、事件总线不可减配）；可以延后简化的是GraphRAG融合排序调优、置信度周期校准任务、图谱信号阈值精调（需求文档§10第4项已注明是纯占位可后补）；文档规范可以放到最后补，但"无会议纪要"单独扣5分，不能省。
- 人力单点风险：智能客服Agent轨道有2人（赵嘉、袁艺铭）互为备份，其余5条轨道均为单人负责，一旦某人进度严重受阻，李清华轨道需优先支援风控（聂柏，关键路径最多）与数据分析（蒋智仁，NL2SQL是关键路径）两条线。
